## ২. ক্লিক-বাই-ক্লিক স্টেপ গাইড (EXACT CLICK-BY-CLICK TESTING)

একজন সাধারণ টেস্টার হিসেবে নিচের ক্রম অনুসারে পরীক্ষা করুন:

---

### টেস্ট কেস ০১: অপারেটর লগইন পরীক্ষা (Authentication)
* **কোন পেজে যাব:** ব্রাউজারে `http://localhost:3000` এ যান।
* **কী Input দেব (ভুল পাসওয়ার্ড):** Password ঘরে লিখুন `wrongpassword123`
* **কোন বাটনে ক্লিক করব:** **`Sign In`** বাটনে ক্লিক করুন।
* **স্ক্রিনে কী দেখাবে:** লাল বক্সে বার্তা দেখাবে: `"Invalid credentials."`
* **কী Input দেব (সঠিক পাসওয়ার্ড):** Password ঘরে আপনার `.env.local` এ সেট করা পাসওয়ার্ডটি লিখুন (যেমন: `sentinai_secure_pass_2026`)।
* **কোন বাটনে ক্লিক করব:** **`Sign In`** বাটনে ক্লিক করুন।
* **স্ক্রিনে কী দেখাবে:** লগইন সফল হবে এবং সরাসরি ড্যাশবোর্ড স্ক্রিন চলে আসবে।
* **কোন ফলাফল দেখলে PASS:** সঠিক পাসওয়ার্ডে ড্যাশবোর্ডে প্রবেশ করলে PASS।
* **কোন ফলাফল দেখলে FAIL:** পাসওয়ার্ড ভুল দিলে বা পেজ হ্যাং হয়ে সাদা হয়ে গেলে FAIL।
* **প্রত্যাশিত HTTP কোড:** ভুল দিলে `401 Unauthorized`, সঠিক দিলে `200 OK` (Set-Cookie: `sentinai_session`)।

---

### টেস্ট কেস ০২: লগআউট পরীক্ষা (Logout Flow)
* **কোন পেজে যাব:** ড্যাশবোর্ডের উপরে ডান কোণায় (TopBar)।
* **কোন বাটনে ক্লিক করব:** **`Sign Out`** বাটনে ক্লিক করুন।
* **স্ক্রিনে কী দেখাবে:** তৎক্ষণাৎ সেশন ডিলিট হয়ে সেন্টিনআই গার্ডিয়ানের **`Sign In`** পেজ চলে আসবে।
* **কোন ফলাফল দেখলে PASS:** আবার লগইন স্ক্রিন আসলে PASS।
* **কোন ফলাফল দেখলে FAIL:** লগআউট করার পরও ড্যাশবোর্ড দেখা গেলে FAIL।
* **প্রত্যাশিত HTTP কোড:** `POST /api/auth/logout` $\to$ `200 OK`।

### টেস্ট কেস ০৩: হোমপেজ ও লাইভ ব্যালেন্স রিড (Homepage Overview)
* **কোন পেজে যাব:** লগইন করে ড্যাশবোর্ডের হোমপেজে (`/`)।
* **কী দেখতে পাব:**
  1. উপরে স্ট্যাটাস ব্যাজ: **`Environment: LIVE_READ_ONLY`** (বা MOCK)।
  2. প্রথম কার্ড: **Native Asset Balance (Sepolia)** — যেমন `61.0876 ETH` এবং নিচে অ্যাড্রেস।
  3. দ্বিতীয় কার্ড: **Supported Token Balances** — যেমন `USDC: 1357.10`, `USDT: 57.00`।
  4. তৃতীয় কার্ড: **Network & Security** — `Sepolia (11155111)`, `Block #119...`, `Armed (Deterministic)`।
* **কোন ফলাফল দেখলে PASS:** সেপোলিয়া টেস্টনেটের আসল ব্যালেন্স ও ব্লক নম্বর লোড হলে PASS।
* **কোন ফলাফল দেখলে FAIL:** সব জায়গায় `—` বা `Unavailable` দেখালে FAIL।

### টেস্ট কেস ০৪: রিড-অনলি প্রশ্ন (Read-Only Balance Query — ইংরেজি)
* **কোন পেজে যাব:** ড্যাশবোর্ডের নিচে **`Agent Command Center`** সেকশনে।
* **ইনপুট বক্সে কী লিখব:** `Show my balance`
* **কোন বাটনে ক্লিক করব:** ইনপুট বক্সের ডানপাশের নীল সেন্ড আইকন ( **`➤`** ) বাটনে ক্লিক করুন (অথবা কিবোর্ডে `Enter` চাপুন)।
* **স্ক্রিনে কী দেখাবে:** নীল রঙের কার্ড আসবে:
  - শিরোনাম: **`Live Wallet Intelligence`**
  - ব্যাজ: **`READ-ONLY · NO SIGNER REQUIRED`** এবং **`FALLBACK PARSER`**
  - ব্যালেন্স গ্রিড: Native ETH, USDC, USDT ব্যালেন্স এবং সেপোলিয়া ব্লক নম্বর।
  - কোনো লাল বা সবুজ এক্সিকিউট বাটন আসবে না।
* **কোন ফলাফল দেখলে PASS:** গ্যাস ফি ছাড়া নিরাপদে ওয়ালেটের তথ্য দেখালে PASS।
* **কোন ফলাফল দেখলে FAIL:** কোনো এরর দেখালে বা ট্রানজাকশন প্রপোজাল তৈরি করলে FAIL।

### টেস্ট কেস ০৫: বাংলা ভাষায় প্রশ্ন (Bengali Read-Only Query)
* **ইনপুট বক্সে কী লিখব:** `আমার ওয়ালেট ব্যালেন্স দেখাও`
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **স্ক্রিনে কী দেখাবে:** ঠিক আগের টেস্টের মতোই নীল কার্ডে লাইভ ব্যালেন্স ও ব্লক তথ্য আসবে।
* **আরেকটি প্রশ্ন দিন:** `বর্তমান নেটওয়ার্ক কী?`
* **স্ক্রিনে কী দেখাবে:** নীল কার্ড: **`Sepolia Network Status`** — Connected to Ethereum Sepolia Testnet [Chain ID: 11155111]।
* **কোন ফলাফল দেখলে PASS:** খাঁটি বাংলা প্রশ্ন সঠিকভাবে বুঝে সঠিক তথ্য দিলে PASS।
* **কোন ফলাফল দেখলে FAIL:** `UNKNOWN_INTENT` দেখালে FAIL।

### টেস্ট কেস ০৬: বৈধ লেনদেন প্রস্তাব (Valid Intent Submission — Phase 1)
* **ইনপুট বক্সে কী লিখব:** `Send 0.05 ETH to alice`
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **প্রসেসিং চলাকালীন কী দেখাবে:** নীল লেখা: `"Phase 1: Analyzing Intent & Evaluating Security Policy..."`
* **বিশ্লেষণ শেষে স্ক্রিনে কী দেখাবে:**
  1. সবুজ ব্যানার: **`POLICY COMPLIANT — Transaction calldata matches requested intent and adheres to user policy.`**
  2. তুলনামূলক টেবিল: **`Semantic Integrity Comparison`** (০টি অমিল/0 Mismatches)।
  3. সবুজ কার্ড: **`Human-in-the-Loop Execution Gate`** যার মধ্যে Proposal ID এবং একটি বড় সবুজ বাটন: **`Confirm & Execute Transaction`** থাকবে।
* **কোন ফলাফল দেখলে PASS:** সবুজ পলিসি কমপ্লায়েন্ট ব্যানার এবং কনফার্ম বাটন আসলে PASS।
* **কোন ফলাফল দেখলে FAIL:** বৈধ নির্দেশ ব্লক হলে বা লাল এরর আসলে FAIL।

* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।

  - সবুজ ব্যানার: **`POLICY COMPLIANT`**।
  - টেবিলে অপারেশন: `TRANSFER`, অ্যাসেট: `ETH`, অ্যামাউন্ট: `0.05 ETH`, প্রাপক: `0xd8dA6...` (Alice)।
  - সবুজ **`Confirm & Execute Transaction`** বাটন দৃশ্যমান হবে।
* **কোন ফলাফল দেখলে PASS:** বাংলা লিপি ও সংখ্যা (`০.০৫`) সঠিক অনুবাদ হয়ে এক্সিকিউশন গেটে আসলে PASS।
* **কোন ফলাফল দেখলে FAIL:** বাংলা বুঝতে না পেরে লাল এরর দিলে FAIL।

### টেস্ট কেস ০৮: ফেইজ ২ এক্সিকিউশন গেট ক্লিক (Phase 2 Execution Gate Testing)
* **কোন বাটনে ক্লিক করব:** টেস্ট কেস ৬ বা ৭-এর সবুজ বাটন **`Confirm & Execute Transaction`** এ ক্লিক করুন।
* **প্রসেসিং চলাকালীন কী দেখাবে:** সবুজ স্পিনার: `"Phase 2: Verifying Keccak-256 Digest & Broadcasting Transaction..."`
* **ফলাফল স্ক্রিনে কী দেখাবে:** লাল কার্ড আসবে:
  - শিরোনাম: **`Execution Blocked / Failed`**
  - বার্তা: **`Error: MISSING_CREDENTIALS: Real execution requires configured private key and RPC URL.`**
  - প্রস্তাব আইডি: `Proposal ID: <uuid>`।
* **কেন এমন দেখাল:** কারণ সিস্টেমে নিরাপদে টাকা পাঠানো রোধ করতে কোনো প্রাইভেট কি কনফিগার করা হয়নি। এটি সিস্টেমের সেফগার্ড।
* **কোন ফলাফল দেখলে PASS:** টাকা না পাঠিয়ে সিস্টেম নিরাপদে `MISSING_CREDENTIALS` এরর দিলে PASS।
* **কোন ফলাফল দেখলে FAIL:** কোনো এরর ছাড়া ক্র্যাশ করলে বা পেজ ফ্রিজ হয়ে গেলে FAIL।

### টেস্ট কেস ০৯: অপরিচিত প্রাপক প্রতিরোধ (Invalid Recipient / Unknown Alias)
* **ইনপুট বক্সে কী লিখব:** `Send 0.05 ETH to evil_hacker`
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **স্ক্রিনে কী দেখাবে:**
  1. লাল ব্যানার: **`EXECUTION BLOCKED — Deterministic verification detected unauthorized or malicious parameters.`**
  2. লাল ব্লকড কার্ড: **`Execution Permanently Prohibited`**
  3. ব্যাজ: **`NON-EXECUTABLE PROPOSAL`**
  4. নিচে কোনো **`Confirm & Execute`** বাটন থাকবে না।
* **কোন ফলাফল দেখলে PASS:** অননুমোদিত ব্যক্তির কাছে টাকা পাঠানো সম্পূর্ণ নিষিদ্ধ হলে PASS।
* **কোন ফলাফল দেখলে FAIL:** এক্সিকিউট বাটন চলে আসলে FAIL (মারাত্মক সিকিউরিটি ত্রুটি)।

---

### টেস্ট কেস ১০: পলিসি লিমিট অতিক্রম (Invalid Amount — Exceeds Policy Cap)
* **ইনপুট বক্সে কী লিখব:** `Send 5 ETH to alice`
* *(ব্যাখ্যা: সিস্টেমে প্রতি লেনদেনে সর্বোচ্চ ১.০ ETH পাঠানোর নিয়ম সেট করা আছে)*
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **স্ক্রিনে কী দেখাবে:**
  - লাল ব্যানার: **`EXECUTION BLOCKED`**
  - সিকিউরিটি ফাইন্ডিংস: `Amount 5 ETH exceeds maximum allowed limit of 1.0 ETH`
  - লাল কার্ড: **`Execution Permanently Prohibited`**
  - এক্সিকিউট বাটন আসবে না।
* **কোন ফলাফল দেখলে PASS:** ১.০ ইথারের বেশি লেনদেন অবিলম্বে ব্লক হলে PASS।
* **কোন ফলাফল দেখলে FAIL:** ৫ ইথার পাঠানোর অনুমতি দিলে FAIL।

---

### টেস্ট কেস ১১: অবৈধ অ্যামাউন্ট ফরম্যাট (Negative / Invalid Number Format)
* **ইনপুট বক্সে কী লিখব:** `Send -0.5 ETH to alice`
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **স্ক্রিনে কী দেখাবে:**
  - লাল কার্ড: `INVALID_AMOUNT: Negative amounts are not allowed.`
  - কোনো ট্রানজাকশন প্রপোজাল তৈরি হবে না।
* **আরেকটি ইনপুট দিন:** `Send 0.1.5 ETH to alice`
* **স্ক্রিনে কী দেখাবে:**
  - লাল কার্ড: `INVALID_AMOUNT: Invalid number format for amount.`
* **কোন ফলাফল দেখলে PASS:** নেগেটিভ বা ভুল দশমিক সংখ্যা ব্লক হলে PASS।

---

### টেস্ট কেস ১২: স্ববিরোধী নির্দেশ ও বাতিলকরণ (Cancellation & Negation Safety)
* **ইনপুট বক্সে কী লিখব (ইংরেজি):** `Send 0.1 ETH to alice but actually do not send anything`
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **স্ক্রিনে কী দেখাবে:**
  - লাল ব্যানার: `EXECUTION BLOCKED`
  - এরর: `CONTRADICTORY_INSTRUCTION: Transaction negation or cancellation detected in command.`
  - কোনো এক্সিকিউট বাটন নেই।
* **ইনপুট বক্সে কী লিখব (বাংলা):** `এলিসকে ০.০৫ ইথ পাঠিও না`
* **কোন বাটনে ক্লিক করব:** সেন্ড বাটন ( **`➤`** )।
* **স্ক্রিনে কী দেখাবে:** তৎক্ষণাৎ স্ববিরোধী/নেতিবাচক নির্দেশ হিসেবে চিহ্নিত করে বাতিল করবে।
* **সান্ত্বনামূলক স্বাভাবিক ইংরেজি বাক্য পরীক্ষা করুন:** `Do not worry, send 0.05 ETH to alice`
* **স্ক্রিনে কী দেখাবে:** এটি বাতিল হবে না! কারণ "Do not worry" কোনো ট্রানজাকশন বাতিলের নির্দেশ নয়। এটি সফলভাবে সবুজ কমপ্লায়েন্ট হবে।
* **কোন ফলাফল দেখলে PASS:** নেতিবাচক নির্দেশ ব্লক হলে এবং স্বাভাবিক সান্ত্বনা বাক্য পাস করলে PASS।

### টেস্ট কেস ১৩: ৫টি নিয়ন্ত্রিত থ্রেট সিনারিও বাটন (Controlled Threat Scenarios)
ইনপুট বক্সের ঠিক নিচে বেগুনি বর্ডারের ৫টি বাটন রয়েছে। একে একে ক্লিক করে পরীক্ষা করুন:

1. **বাটন ১ ক্লিক করুন: `Phishing: 1M USDC Approval`**
   - স্ক্রিনে বেগুনি কার্ড আসবে: **`Controlled Security Demonstration Fixture (DEMO / SIMULATED)`**
   - টেবিলে দেখাবে: ইউজার চেয়েছিল স্বাভাবিক অ্যাপ্রুভাল কিন্তু বাইটক্যালকুলেশনে ১০ লাখ USDC অ্যাপ্রুভাল চেয়ে বসে আছে।
   - স্ট্যাটাস: `AMOUNT MISMATCH` ও `BLOCKED`।
   - ব্যাজ: `NON-EXECUTABLE DEMO`। কোনো এক্সিকিউট বাটন নেই।

2. **বাটন ২ ক্লিক করুন: `Drainer: Attacker Spender`**
   - টেবিলে দেখাবে: অ্যাপ্রুভড স্পেন্ডার একজন অপরিচিত অ্যাটাকার।
   - স্ট্যাটাস: `ADDRESS MISMATCH` ও `BLOCKED`।

3. **বাটন ৩ ক্লিক করুন: `Spoof: Contract Mismatch`**
   - টেবিলে দেখাবে: আসল টোকেন কন্ট্রাক্টের বদলে ফেক স্পুফড কন্ট্রাক্ট বসানো হয়েছে।
   - স্ট্যাটাস: `TOKEN CONTRACT MISMATCH` ও `BLOCKED`।

4. **বাটন ৪ ক্লিক করুন: `Network: Mainnet Confusion`**
   - টেবিলে দেখাবে: সেপোলিয়া টেস্টনেটের জায়গায় মেইননেট চেইন আইডি কল করা হয়েছে।
   - স্ট্যাটাস: `WRONG CHAIN` ও `BLOCKED`।

5. **বাটন ৫ ক্লিক করুন: `Safe: 50 USDC Approval`**
   - টেবিলে সব প্যারামিটার সবুজ মিলবে।
   - কিন্তু এটি ডেমো ফিক্সচার হওয়ায় বেগুনি কার্ডে পরিষ্কার লেখা থাকবে: `NON-EXECUTABLE DEMO`। একে কোনোভাবেই ব্লকচেইনে সাইন করা সম্ভব নয়।

* **কোন ফলাফল দেখলে PASS:** ৫টি বাটনই ক্লিক করার পর নিখুঁত ডিসেকশন দেখাবে এবং কোনো অবস্থাতেই এক্সিকিউট বাটন আসবে না।

---

### টেস্ট কেস ১৪: জেমিনি এআই ফলব্যাক ব্যাজ (AI Fallback Provenance)
* যেকোনো কমান্ড সাবমিট করার পর ব্যানারের উপরের ডানপাশে খেয়াল করুন।
* **কী দেখতে পাবেন:** নীল রঙের পিল ব্যাজ: **`FALLBACK PARSER`**।
* **এর অর্থ কী:** সিস্টেম সততার সাথে জানাচ্ছে যে লাইভ জেমিনি কোটা শেষ থাকায় লোকাল ফলব্যাক রেজেক্স ইঞ্জিন দিয়ে কাজটি করা হয়েছে। কোনো ভুয়া জেমিনি আউটপুট দাবি করা হচ্ছে না।
* **কোন ফলাফল দেখলে PASS:** নীল `FALLBACK PARSER` ব্যাজ দেখালে PASS।

---

### টেস্ট কেস ১৫: পেজ রিফ্রেশ ও ডাটাবেজ স্থায়িত্ব (Refresh / Persistence)
* কোনো কমান্ড দেওয়ার পর ব্রাউজারে `F5` বা রিফ্রেশ বাটনে ক্লিক করুন।
* **কী দেখতে পাবেন:**
  - আপনাকে পুনরায় লগইন করতে হবে না (কারণ কুকি সেশন ৩০ মিনিট কার্যকর থাকে)।
  - হোমপেজের লাইভ ব্যালেন্স পুনরায় রিয়েল-টাইমে লোড হবে।
* **কোন ফলাফল দেখলে PASS:** সেশন নষ্ট না হয়ে পেজ সহজে রিলোড হলে PASS।

## ৩. আসল বনাম নকল যাচাই করার উপায় (HOW TO VERIFY REAL VS FAKE)

একজন টেস্টার হিসেবে আপনি ব্রাউজারের ডেভেলপার টুলস (`F12`) দিয়ে নিজেই প্রমাণ যাচাই করতে পারেন:

### ক. আসল টেস্টনেট রিড বনাম মক ডাটা যাচাই:
1. ব্রাউজারে কিবোর্ডের `F12` চেপে **Developer Tools** খুলুন।
2. **Network** ট্যাবে যান এবং পেজ রিফ্রেশ দিন।
3. আপনি দেখতে পাবেন সার্ভার থেকে রেন্ডার হওয়া পেজে সেপোলিয়ার আসল ব্লক নাম্বার (যেমন `#11906...`) আসছে।
4. যেকোনো সেপোলিয়া ব্লক এক্সপ্লোরারে (যেমন `https://sepolia.etherscan.io`) যান।
5. ড্যাশবোর্ডে দেখানো ব্লক নাম্বার ও টেস্টনেটের বর্তমান ব্লক নাম্বার মিলিয়ে দেখুন—দুটো হুবহু এক! এটি কোনো স্ট্যাটিক ফেক নাম্বার নয়।

### খ. জেমিনি বনাম ফলব্যাক পার্সার যাচাই:
1. স্ক্রিনের ব্যানারে লক্ষ্য করুন ব্যাজটি সবুজ নাকি নীল।
2. যদি নীল হয় এবং লেখা থাকে `FALLBACK PARSER`, তবে নিশ্চিত থাকুন এটি লোকাল ফলব্যাক ইঞ্জিন।
3. যদি জেমিনি লাইভ হতো, তবে সবুজ ব্যাজে লেখা থাকত `LIVE AI` এবং রেসপন্স টাইম (যেমন `240ms`)।

### গ. আসল সিকিউরিটি ব্লকিং বনাম কেবল চোখের ধোঁকা (UI Warning):
1. অনেকে শুধু ইউআইতে লাল বাটন হাইড করে রাখে, কিন্তু ব্যাকএন্ডে এপিআই কল দিলে কাজ হয়ে যায়।
2. সেন্টিনআই গার্ডিয়ানে আপনি যদি ব্রাউজার কনসোল দিয়ে জোরপূর্বক `authorizeAndExecute(proposalId)` কল করেন, ব্যাকএন্ডের সিকিউরিটি গেট ২.৫ (`FIXTURE_EXECUTION_BLOCKED`) এবং গেট ৮ সরাসরি সার্ভার লেভেলে রিকোয়েস্ট রিজেক্ট করে দেবে। এটি কেবল ইউআই লুকানো নয়, সার্ভার সাইড হার্ড ব্লকিং।

## ৪. নিরাপদ টেস্টনেট ভ্যালিডেশন (SAFE TESTNET VALIDATION)

### বর্তমান কোড কি সরাসরি সেপোলিয়ায় রিয়েল ট্রানজাকশন পাঠাতে সক্ষম?
* **উত্তর: হ্যাঁ, কোড প্রস্তুত রয়েছে, কিন্তু সুরক্ষার জন্য চাবি (Private Key) খালি রাখা হয়েছে।**
* `src/core/execution/controller.ts` ফাইলে `viem` লাইব্রেরি ব্যবহার করে সেপোলিয়া টেস্টনেটে সাইন ও ব্রডকাস্ট করার পূর্ণাঙ্গ কোড রয়েছে (`broadcastTransaction`, `waitForReceipt`)।
* কিন্তু ডিফল্ট `.env` ফাইলে কোনো প্রাইভেট কি নেই। এটি একটি সচেতন নিরাপত্তা সিদ্ধান্ত যাতে কোনো টেস্টার বা ডেভেলপারের অজান্তে টেস্টনেটে গ্যাস খরচ বা ফান্ড ট্রান্সফার না হয়ে যায়।

### নিরাপদ উপায়ে টেস্টনেট লাইভ এক্সিকিউশন টেস্ট করার ন্যূনতম ধাপ:
> [!CAUTION]
> **কখনো আপনার মেইননেটের আসল পার্সোনাল ওয়ালেটের প্রাইভেট কি ব্যবহার করবেন না!**

যদি আপনি বাস্তবে টেস্টনেটে লেনদেন ঘটিয়ে দেখতে চান:
1. মেটামাস্কে একটি একদম নতুন সম্পূর্ণ খালি টেস্ট ওয়ালেট তৈরি করুন।
2. গুগল থেকে `Sepolia faucet` থেকে সামান্য ফ্রি টেস্টনেট ইথার (যেমন ০.০৫ সেপোলিয়া ETH) সংগ্রহ করুন।
3. আপনার প্রজেক্টের `.env.local` ফাইলে ভেরিয়েবলটি দিন:
   ```env
   AGENT_PRIVATE_KEY=0x<আপনার_নতুন_টেস্ট_ওয়ালেটের_প্রাইভেট_কি>
   ```
4. এরপর কমান্ড রান করুন: `npm run dev`
5. এখন ব্রাউজারে কমান্ড দিন: `Send 0.01 ETH to alice`
6. সবুজ বাটন **`Confirm & Execute Transaction`** এ ক্লিক করুন।
7. সিস্টেম ট্রানজাকশন সাইন করবে, ব্রডকাস্ট করবে এবং ব্লক কনফার্মেশনের পর আসল **Transaction Hash** (যেমন `0x7a8b...`) স্ক্রিনে প্রদর্শন করবে যা সেপোলিয়া ইথারস্ক্যানে দেখা যাবে!
